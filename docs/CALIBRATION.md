# Калибровка и поиск неисправностей

## Порядок проверки новой машинки

Проверять по одной части, от простого к сложному. Удобнее всего тестовыми прошивками (см. FIRMWARE.md).

| # | Что | Как | Норма |
|---|---|---|---|
| 0 | Понижайки | мультиметр, до подключения ESP | 5.0 В и 9.0 В |
| 1 | ESP + Wi-Fi | основная прошивка, светодиод | жёлтый/зелёный |
| 2 | TOF + серва | `sensortest` | расстояние совпадает с рулеткой (±2 см), серва 0–180°, 180° — влево |
| 3 | MPU6050 | `sensortest` | в покое курс стоит; повернуть влево — курс растёт (иначе `GYRO_SIGN -1`) |
| 4 | Ультразвуки | `sensortest` | «ок, ~14 зам/с», расстояние до руки |
| 5 | ИК пола | телеметрия `cliff` | на полу 0, поднять — 1 |
| 6 | Моторы (колёса в воздухе) | `drivetest`, W/A/S/D | W — вперёд, A — налево; иначе галочки → `config.h` |
| 7 | Энкодеры | `drivetest`, крутить рукой / моторами | 1 оборот ≈ 40 фронтов, все 4 считают |
| 8 | Порог ШИМ | `drivetest` `/raw` | минимальный ШИМ, при котором колёса трогаются → `MOTOR_PWM_MIN` |
| 9 | На полу | консоль: `fwd 500`, `turn 90` | ~50 см, ~90° |
| 10 | Скан | интерфейс «Скан» | точки на карте, похожие на комнату |

## Неисправности, которые уже встречались

| Признак | Причина | Решение |
|---|---|---|
| Едет по маршруту рывками, колёса то стоят, то буксуют | заданная скорость ниже порога трогания | скорости по замеру, `MOTOR_PWM_MIN` как нижняя граница ШИМ |
| Моторы пищат, крутятся только на максимуме | ШИМ 10 кГц слишком высокий для MX1508 + TT | `MOTOR_PWM_FREQ 500` |
| В воздухе колёса одной стороны крутятся с разной скоростью | у каждого редуктора своё трение; на полу колёса стороны связаны через пол | норма; регулятор держит скорость стороны |
| Машинка дёргается и только поворачивает туда-сюда | одна сторона перепутана/инвертирована | `drivetest` → галочки → `PIN_MOT_*`, `MOTOR_*_INVERT` |
| В журнале «защита: stall», скан прерывается | энкодеры не считают (питание, провод, контакт) | проверить счётчики в `drivetest`; уровни `encpin` |
| Энкодер: светодиод модуля мигает, а импульсов 0 | плохой контакт провода D0 → ESP | обжать/пропаять, поменять провод |
| Вывод энкодера всегда 0 при подтяжке | провод замкнут на GND / сидит не на том контакте | проверить провод |
| Ультразвук: на ECHO постоянно 1 | у датчика нет 5 В / GND, или ECHO не на том канале HW-209 | питание датчика, канал |
| Ультразвук: импульсы редкие | Arduino `attachInterrupt` теряет фронты; UART1 занимает GPIO15/16 | исправлено в `hw.cpp` / `tof.cpp` |
| Скан рисует дуги, дальность ~1.5 м, мало точек | у TOF400F с завода период измерения 500 мс: одно расстояние повторялось на 8 углах подряд | рег. 0x05 = 50 мс (прошивка ставит сама); замер — только после остановки сервы |
| TOF не отвечает (0 байт) | нет питания или RX/TX не на тех выводах | `sensortest` сам перебирает варианты |
| TOF выдаёт мусор | провод сидит на SDA/SCL вместо TXD/RXD | по распиновке модуля: TXD, RXD, SCL, SDA, GND, VIN |
| На карте машинка медленно крутится, стоя на месте | сдвиг нуля гироскопа после включения моторов | исправлено: подстройка нуля в покое до 8 °/с |
| ИК пола «пропасть» на полу | датчик высоко / потенциометр | 1–2 см до пола, подкрутить; проверить `cliffraw` |
| Машинка в Wi-Fi, но сервер «ждёт машинку» | файрвол режет UDP 4210 | `sudo ufw allow 4210/udp` |
| «Не подключается» после перезагрузки компа | сервер не запущен | служба systemd (PC.md) |
| Прошивка по воздуху: «No response from device» | файрвол режет обратное соединение | `sudo ufw allow 3233/tcp` |
| Wi-Fi не подключается | сеть 5 ГГц | только 2.4 ГГц |
| Страница теста показывает старое | кэш браузера | закрыть вкладку, открыть заново (страницы отдаются с `no-store`) |
| Монитор порта молчит после прошивки | DTR/RTS держат плату / USB переподключился | открыть монитор заново, RST |
